# 研究问题与实验取舍

## 研究目标

研究长上下文下投机解码的成本与收益，优先采用容易解释、容易复现的实现。历史 KV 是否有效，需要同时看信息选择、接受长度、草稿耗时和完整解码耗时。提升不是预设结论；简历最终应依据验证后的结果修改。

## 论文给出的启发

- [MagicDec，v5](https://arxiv.org/html/2408.11049v5)：长上下文与 batch 会改变权重、KV 读取和验证的相对成本，稀疏 Draft KV 的选择成本也必须计入。本研究据此按长度与并发分别测量；论文的多卡大 batch 结果不能直接移植到单卡、并发 1/4。
- [LongSpec，v4](https://arxiv.org/html/2502.17421v4)：Draft 的记忆开销、长位置泛化和 Target 验证实现是不同问题。本项目先使用已有 DSpark checkpoint，不把需要重新训练的位置设计直接套到它上面。
- [SparseSpec-L，v1](https://arxiv.org/html/2607.27735v1)：回收历史信息和选择投机长度应服务于每轮效率。本项目把它作为后续方向；当前 FIA 接口没有直接暴露完整 attention 权重，额外计算重要性并不免费，因此先做请求级文本检索和廉价对照。

这些论文提出了不同架构和实验条件。此处借鉴可检验的问题，没有把它们的收益写成本项目结果，也没有把 BM25 页选择称为论文方法的完整复现。

## 第一版真实分页方案

[paged_history.py](paged_history.py) 保留完整 KV 存储，只修改 Draft 的读块表。Target 仍读取完整上下文。请求开始时，从原始 prompt 中早于初始局部窗口的完整页选择历史锚点；后续仅推进局部窗口。问题 token 来自请求的 `query_token_ids`，不使用答案或生成结果。

先比较 BM25 与 uniform、sink、recent 三种廉价选择，再比较缓存与每步重新检索。局部预算和历史预算必须是实际 attention page 的整数倍。局部窗口的左端向页边界取整，最后一页按真实长度读取，因此需要报告真实读取长度，不能声称始终严格读取 2176 个 token。DSpark query span 已包含在传入长度中，不能再次添加 K。

每个 KV group 有独立的输出块表；各组从同一份原始 metadata 创建浅拷贝，避免重复截断。只压缩读取地址，原始 slot mapping、RoPE 绝对位置和完整缓存不变。首版显式同步一次长度到 CPU，各组按页大小复用；这一成本必须在后续 Profiling 中单列。

当前仅支持文本、非因果的 DSpark Draft、eager Draft 和未压缩 KV。Target 可以使用图解码，但该路径仍需单独回归。没有声明 Draft graph replay、上下文并行或减少完整 KV 分配量已经实现。

## 需要回答的瓶颈问题

| 环节 | 要测什么 | 什么结果会否定当前方案 |
| --- | --- | --- |
| 索引与检索 | 请求首次构建、缓存命中、每步重新排序 | 首次成本无法在生成长度内摊薄，或检索选择不能提高接受长度 |
| 分页准备 | 块表 gather、CPU 长度同步、页对齐多读 | 准备开销抵消读取减少；小 batch 尤其容易出现 |
| Draft backbone 与 attention | 全部时间及 attention 占比 | backbone 的非 attention 部分主导，减 KV 也难以改善每轮时间 |
| Markov Head | 预测 K 个位置的耗时及逐位置接受情况 | 后续位置接受很差，却仍支付预测与验证成本 |
| Target verification | 随 K、context、batch 的成本变化 | 多 token 验证的额外成本超过减少调用次数的收益 |
| 端到端 | 无 Profiler 的输出事件 TPOT、吞吐、TTFT | 接受率提高但总耗时仍增加，或只有 Profiler 内观察到“收益” |

稳态下可用每轮耗时除以实际提交 token 数估计单位 token 成本：`C = T_round / E[M]`。在输入、执行模式和统计区间匹配的前提下，历史方案胜过窗口，需要其接受长度的相对增长超过每轮耗时的相对增长。这个式子指导实验，不能替代实际端到端测量；prefill、尾部截断和请求完成须另外记录。

## 验证顺序

先检查 CPU 地址与多 group 接线，再用真实 FIA 对照绝对位置的 FP32 attention，最后做完整模型贪心 token 回归。每层门槛只证明本层：组件数值一致不等于模型分布一致，短输入通过也不等于长输入与所有并发通过。

在正确性通过后，使用相同输入比较 AR / Full KV / Window / Anchors，覆盖 4K、16K、24K 和并发 1/4；长自然回答使用 512-token 固定输出，短答案任务用 EOS 终止做质量回归。后续加入真实长文档任务，避免仅凭合成检索样本下普遍结论。

每轮保留原始输出、接受计数、实际输出事件、软件和模型校验信息、冻结源码及失败日志。Profiler 单独运行，绘图只消费已验证的原始数据。同步调试模式可以帮助定位错误，其耗时不能当作优化后的正式性能。
